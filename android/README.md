# Pulsar for Android

Live heart rate from the front camera, computed entirely on the phone. The app has no internet
permission. **Research prototype, not a medical device.**

| Module | What | Needs |
|---|---|---|
| `core/` | Pure Kotlin port of the Python live path: sRGB LUT, landmark patches and view angles, adaptive skin mask, trace extractor, timestamp resampler, live window, ONNX Runtime wrapper, abstain policy, golden-file check | JDK 17 only |
| `app/` | CameraX (front camera, 30 fps, RGBA), MediaPipe Face Landmarker (VIDEO mode), ONNX Runtime Mobile (XNNPACK), overlay UI, CSV session log, on-device self-test | Android SDK |

`core` mirrors `pulsar.preprocess` operation for operation, down to numpy's float32 rounding. Its tests
check it against fixtures generated by the Python reference:

- extractor: bit-identical patch means
- resampler and live window: within 1e-5
- full model through ONNX Runtime: within 1e-4 on the pulse waveform (worst case 7e-5), HR within 0.05 bpm

## Build

1. Export a model from the Python side. This writes `outputs/export/<name>/` with `tracenet.onnx`,
   `model_meta.json` and `golden/`:
   ```bash
   uv run --no-sync python scripts/export_model.py --model runs/<run>/best.pt --name <name>
   ```
   The face landmarker model is `data/assets/face_landmarker.task`, which the Python demo downloads.
2. Open `android/` in Android Studio. Put the SDK on D: if C: is full, and set `GRADLE_USER_HOME` to a
   folder on D: as well. Then run the `app` configuration on a phone.
   The build copies the model files into `app/src/main/assets/`, which is gitignored.
   Choose the export with `pulsar.export` in `gradle.properties`, or pass `-Ppulsar.export=<name>`.
3. Command line:
   ```bash
   cd android
   ./gradlew :app:installDebug                 # build and install
   ./gradlew :app:connectedAndroidTest         # golden files on the phone (parity + latency)
   ./gradlew -Ppulsar.coreOnly=true :core:test # core tests, no Android SDK needed
   ```
   Without Gradle at all: `bash scripts/android_core_tests.sh fetch`, then `bash scripts/android_core_tests.sh`.

## Using the app

- Hold the phone at arm's length with your face lit from the front. The first reading appears after about 10 s.
- Status messages:
  - **Hold still, measuring...**: the 10 s buffer is still filling.
  - **No face**: no face is detected in the frame.
  - **Low signal**: the calibrated confidence is below τ = 0.5, the same threshold the evaluation uses, so
    the phone shows readings as often as the evaluation did.
- **Log** writes `pulsar_session_<time>.csv` to `Android/data/dev.pulsar.app/files/`, for comparison with a
  fingertip oximeter. That comparison is a personal sanity check, not evaluation data.
- **Self-test** reruns the golden files on the phone and reports parity and model latency. The budget is 50 ms.

## Keeping the port in sync

Run `uv run --no-sync python scripts/make_android_fixtures.py` after any change to `pulsar.preprocess`, then
commit the regenerated `core/src/test/resources/fixtures/`. `tests/test_fixtures.py` fails while they are stale.
The extractor's constants are read from `model_meta.json` (`patch_spec`, `extractor`, `window`); the
Kotlin defaults only cover older metadata files.
